# Doris 数仓实验项目方案

## 1. 方案定位

该方案用于指导一个基于 Doris 的数仓实验项目落地，重点不是交付生产级平台，而是通过统一业务场景，验证不同模型与分层方式在分析问题上的表达差异。

方案以营销活动分析为统一实验场景，以 Doris 为主要查询与建模验证载体，按三阶段逐步推进。

## 2. 总体路线

### 第一阶段：建模与分层对比实验

第一阶段聚焦三个实验视角：

1. 维度建模方案
2. Medallion Architecture 方案
3. 维度建模与 Medallion 结合方案

该阶段目标不是一次性做大，而是构造一组足够说明问题的小型实验数据，并输出三套能够直接比较的结果。

产出应至少包括：

- 对应表结构
- 装载或加工 SQL
- 典型分析 SQL
- 查询结果样例
- 可选对比表

### 第二阶段：数仓分层与模型应用沉淀

第二阶段在第一阶段结果基础上，进一步整理更稳定的数仓分层方式与模型应用方式。

重点是把前一阶段的“对比验证”沉淀为“可复用的分层和模型实践”，并明确哪些设计更适合后续扩展。

### 第三阶段：实时数仓扩展

第三阶段再引入：

- 实时处理链路
- 脏数据问题
- 更大规模数据
- 秒级查询与处理目标

这一阶段才开始补充前两阶段刻意延后的复杂度。

## 3. 第一阶段详细方案

### 3.1 业务主题

统一使用营销活动分析场景。

建议围绕以下核心对象组织数据：

- 活动
- 用户
- 渠道
- 触达/曝光
- 点击
- 领取
- 下单
- 支付

通过这些对象支撑典型分析问题，例如：

- 活动带来的曝光、点击、转化表现
- 不同渠道的活动效果差异
- 不同用户群在活动中的转化差异
- 活动 ROI 或漏斗表现

### 3.2 三类实验方案

#### A. 纯维度建模

以事实表 + 维度表方式组织模型，重点体现：

- 主题清晰
- 指标归属明确
- 面向分析的星型或雪花结构
- 查询逻辑更接近传统 BI / 数仓分析范式

#### B. 纯 Medallion Architecture

以 Bronze / Silver / Gold 分层组织数据，重点体现：

- 原始数据到清洗数据到分析结果数据的演进路径
- 不同层的责任边界
- 数据加工链路的可追踪性
- 分层组织对分析的支持方式

#### C. 维度建模 + Medallion 结合

在 Bronze / Silver / Gold 分层框架中，引入维度建模思想，重点体现：

- Bronze 保留原始或近原始数据
- Silver 进行标准化、清洗、轻度整合
- Gold 采用面向分析的事实维度模型

该方案通常最贴近企业真实实践，也是默认推荐主线。

### 3.3 第一阶段推荐策略

虽然要同时保留三类方案做比较，但实施顺序建议为：

1. 先统一营销活动分析口径与样例数据
2. 再优先落地“维度建模 + Medallion 结合”主线
3. 然后拆出“纯维度建模视角”与“纯 Medallion 视角”形成可比较结果

这样更容易保证：

- 业务口径一致
- 比较维度一致
- 成本可控

## 4. 数据策略

### 4.1 初期策略

当前阶段采用程序模拟数据。

要求：

- 数据要贴近真实营销活动分析语境
- 数据规模先控制在小型实验版
- 重点保证样本能支撑漏斗、渠道、活动效果等典型分析

### 4.2 延后内容

以下内容明确延后到第三阶段：

- 更大规模数据
- 脏数据治理
- 更复杂的实时链路
- 更强的性能压测

## 5. 输出形式

当前阶段的核心输出不是代码框架本身，而是可比较的分析产物。

建议固定输出以下几类内容：

1. 表结构说明
2. SQL 脚本
3. 查询结果样例
4. 方案差异对比表
5. 关键结论说明

其中：

- 表结构说明负责展示模型表达
- SQL 负责展示加工与查询方式
- 查询结果负责展示最终分析可用性
- 对比表负责归纳差异
