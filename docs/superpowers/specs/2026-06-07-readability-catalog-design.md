# 项目可读性增强设计

## 1. 目标

当前项目的问题不是缺少产物，而是用户无法快速判断：

- 现在做到哪一步
- 原始数据有哪些表
- 三种模型如何组织
- 表结构、数据字典、血缘信息去哪里看

本次设计的目标是提升项目可读性，而不是建设一个完整的 Web 系统。

本次修订新增两个明确目标：

- 模型对比区可以直接下钻到“模型 -> 层级 -> 表 -> 字段”
- 每张表可以直接看到前 2 行样例数据，不跳转到 CSV

## 2. 设计原则

- 以阅读和导航为主，不做复杂系统交互
- 以现有 Markdown 文档为主体，只补一个静态 HTML 总览页
- 优先展示项目进展、源数据、模型分层、数据字典、表级血缘
- 第一版只做表级血缘，关键指标补少量字段映射说明
- 允许使用少量原生 JavaScript，但只用于展开、切换和显示详情

## 3. 推荐方案

采用 `一个 HTML 总览页 + 少量 Markdown 详情页 + 少量原生 JavaScript` 的方式。

### 3.1 HTML 总览页职责

总览页负责统一入口和轻量下钻，包含以下区块：

1. 项目进展
2. Dataset 总览
3. 三种模型对比
4. 分层与表导航
5. 文档快速入口

总览页提供跳转和轻量展开，不承担完整数据目录系统职责。

### 3.2 总览页交互职责

总览页只新增以下轻量交互：

1. 点击源表，展开字段结构和前 2 行样例数据
2. 点击模型卡片，展开模型说明和层级结构
3. 点击层级，展开该层表清单
4. 点击表名，展开字段、前 2 行样例和一句话血缘

不引入搜索、筛选、分页、CSV 跳转、复杂状态管理。

### 3.3 Markdown 详情页职责

- `docs/project-status.md`：当前进展、已完成产物、待补齐产物
- `docs/data-dictionary.md`：统一源数据字典与模型层补充说明
- `docs/data-lineage.md`：三种模型的表级血缘说明
- `docs/specs/schema-comparison.md`：三种模型结构差异对比

## 4. 信息结构

### 4.1 项目进展

回答“现在做到了哪里”，建议展示：

- 当前阶段
- 已完成产物
- 待补齐产物
- 推荐阅读顺序

### 4.2 Dataset 总览

回答“原始数据有哪些”，建议展示：

- 表名
- 业务含义
- 主键或关联键
- 字段数
- 点击后展开字段结构
- 点击后展示前 2 行样例数据

### 4.3 三种模型对比

回答“方案差异是什么”，建议展示：

- `dimensional`
- `medallion`
- `hybrid`

每种模型展示：

- 模型目标
- 分层方式
- 当前已有表
- 对应 SQL 目录
- 点击卡片后展开详情

### 4.4 分层与表导航

回答“每层有什么表”，建议展示：

- 层名
- 层职责
- 表清单
- 点击表后展开字段结构
- 点击表后展示前 2 行样例数据
- 点击表后展示一句话血缘

### 4.5 表详情展示

每张表展开后统一展示以下信息：

- 表名
- 所属模型
- 所属层级
- 一句话业务含义
- 字段结构
- 前 2 行样例数据
- 一句话血缘

## 5. 数据字典设计

数据字典采用两层结构：

### 5.1 统一源数据字典

覆盖原始表，例如：

- `campaigns`
- `users`
- `channel_touchpoints`
- `click_events`
- `coupon_claim_events`
- `order_events`
- `payment_events`

### 5.2 模型层补充说明

只补模型加工后的表，不重复抄写整份源表定义。

每张表至少说明：

- 表名
- 所属模型
- 所属层级
- 业务用途
- 关键字段
- 上游来源

源数据表和模型层表在总览页中都可以复用同一份说明结构。

## 6. 血缘设计

第一版只做表级血缘，避免信息过重。

展示原则：

- 在 HTML 总览页中给出简短来源说明
- 在 `docs/data-lineage.md` 中给出完整表级路径
- 对关键指标保留少量字段映射说明

示例：

- `payment_events -> silver_payments -> gold_campaign_funnel`
- `payment_amount -> paid_amount`

## 7. 第一版范围

第一版只包含：

- 1 个带少量原生 JavaScript 的静态 HTML 总览页
- 1 份新增血缘文档
- 对现有进展文档和数据字典的补充整理
- 对三种模型的分层和表清单整理
- 对源表和模型表增加前 2 行样例数据展示

第一版不包含：

- 搜索
- 筛选器
- 多页面应用
- 自动解析 SQL 生成目录
- 全量字段级血缘图谱
- 跳转查看完整 CSV

## 8. 文件规划

- `docs/catalog.html`：项目总览入口页
- `docs/project-status.md`：项目状态页
- `docs/data-dictionary.md`：数据字典
- `docs/data-lineage.md`：表级血缘说明
- `docs/specs/schema-comparison.md`：模型对比说明

## 9. 页面行为边界

允许的 JS 行为：

- 切换当前选中的模型
- 控制源表、层级、表详情的展开和收起
- 在页面内显示静态内嵌的字段和样例数据

不允许的 JS 行为：

- 动态请求后端数据
- 加载完整 CSV
- 做复杂状态同步
- 做独立路由或页面跳转

## 10. 成功标准

完成后，用户应能在几分钟内回答：

1. 这个项目当前进展如何
2. 原始数据集有哪些表
3. 三种模型各自如何分层
4. 某张表的字段和业务含义是什么
5. 某张表从哪里来，最终服务什么分析
6. 某张表的前 2 行样例数据长什么样
