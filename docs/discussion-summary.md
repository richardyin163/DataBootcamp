# Doris 数仓实验项目讨论结论

## 项目目标

本项目是一个用于验证不同数仓建模与分层方式差异的实验性数据开发 demo。

目标优先级如下：

1. 优先验证模型表达能力
2. 在真实业务分析语境下比较不同建模与分层方式
3. 通过可执行 SQL、表结构与查询结果体现差异
4. 暂不优先追求大规模与复杂脏数据治理

## 业务场景

当前统一采用营销活动分析场景。

该场景用于承载后续三类方案的对比：

- 纯维度建模
- 纯 Medallion Architecture
- 维度建模与 Medallion 结合

## 阶段划分

### 第一阶段：维度建模 + Medallion Architecture 对比验证

第一阶段聚焦三个方向的对比学习与实验验证：

1. 维度建模
2. Medallion Architecture（Bronze / Silver / Gold）
3. 维度建模 + Medallion Architecture 结合

这一阶段需要形成 3 份可比较的产物，核心比较对象包括：

- 表结构表达方式
- 数据组织方式
- 分析查询写法
- 查询结果呈现方式
- 模型在营销活动分析中的表达能力差异

### 第二阶段：数仓分层与模型应用

第二阶段在第一阶段实验结论基础上，进一步沉淀数仓分层与模型应用方式。

重点不是重新比较概念，而是把前一阶段得到的认识转化为更稳定的分层与应用实践。

### 第三阶段：实时数仓

第三阶段再引入实时能力、脏数据与更大数据规模。

当前已确认：

- 实时目标是秒级
- 当前阶段查询 10 秒内可接受
- 脏数据处理放到第三阶段考虑
- 更大规模数据也放到第三阶段再引入

## 数据策略

当前数据策略如下：

- 初期采用程序模拟数据
- 数据范围先做小型实验版
- 先保证能清晰展示模型差异
- 后续在第三阶段再扩大规模

虽然目标偏实验验证，但希望尽量贴近真实业务分析场景，而不是纯教学示例数据。

## 当前主要交付物

当前预期交付物包括：

- SQL
- 表结构定义
- 查询结果
- 可选的对比表格

说明：

- 结果不仅要有最终查询结果，也要保留过程性产物
- 输出更偏向“可分析、可比较、可验证”

## 性能与范围边界

当前阶段边界如下：

- 以模型表达能力优先，不以极致性能优先
- 查询在 10 秒内可接受
- 数据规模先小型化
- 暂不引入复杂脏数据治理
- 暂不把重点放在完整实时链路

## 目录与工程约束

已确认的工程约束如下：

1. 当前项目下所有 docker 相关内容放入单独文件夹
2. 本次讨论结论需要记录到 docs 目录
3. 方案文档需要记录到 docs 目录

目前项目中已存在 docker 目录，后续 docker-compose、prometheus 及相关内容应继续归拢在该目录下维护。

## 当前已确认、暂不再反复讨论的事项

- 勋章模型这里明确指 Medallion Architecture，不是业务勋章发放体系
- 业务场景统一改为营销活动分析
- 第一阶段必须同时覆盖维度建模、Medallion、以及两者结合
- 输出以 SQL + 表结构 + 查询结果为主
- 小型实验版优先于大而全方案
- 第三阶段再考虑脏数据与更大规模
